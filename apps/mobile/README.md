# healthy · Flutter 个人健康客户端

应用名统一为小写 `healthy`；顶部和桌面图标使用已确认的纯叶片 Logo。SVG 与网页共用仓库母版，原生图标由脚本导出。更新桌面名称和图标需要重新构建并安装客户端。

健康首页、生理指标、个人记录、活动统计、训练计划、饮食记录、食谱推荐与膳食指南，页面分层与网页版一致。右下角“更多”显示完整菜单；可自选 1–4 个 Dock 入口并拖动排序，设置保存在本机。健康报告在“更多”中紧接健康首页，也可自选加入 Dock；支持日报/周报阅读与既有生成、定时设置。健康首页改为数据密集的只读驾驶舱，直接展示身体指标、摄入与营养、餐食明细、最近已完成的日报/周报摘要、运动和个人记录；首页卡片不再跳转，报告长摘要可原位展开。

头部按钮切换 Light / Dark 并记住选择。连接设置和 Dock 设置在“更多”中。安装包内置的服务地址由构建注入：`--dart-define=HEALTH_API_URL=...`，正式发布时统一由 `scripts/deploy-mobile.py` 从项目根目录未提交的 `.env` 读取，源码仓库不保存实际地址。手机需要能访问该地址；当前服务尚无账号登录。

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
flutter run
```

Android 在“更多 → 应用更新”手动检查当前后端发布的最新版，展示版本、更新说明与下载进度。下载后校验大小、SHA-256、包名、递增版本号及与当前安装一致的签名，再打开系统安装界面。首次需在系统设置中允许 healthy 安装应用，返回后点击“继续安装”；取消安装后可重新打开。失败可重试；覆盖安装保留本机设置和服务端记录。iOS 暂不支持此 APK 更新方式。

日常部署在仓库根目录运行 `python3 scripts/deploy-mobile.py`，自动递增版本、检查、构建、发布并经 3060 验证，无需手改版本号。

饮食记录先展示每日摄入概览，近七天热量平衡与营养趋势按需展开；餐食按日期分组，每日完整营养可展开阅读。单餐列表保留照片与四项营养摘要，独立详情以逐项食物卡片展示份量和完整数值。饮食记录保留拍照、相册、多轮澄清与草稿确认、手工录入、编辑删除及网页共享。相机/相册需要设备授权；模型估算需用户核对。保存失败保留当前输入，可重试。数据在服务端 PostgreSQL，本机仅存连接、菜单和主题偏好。膳食指南使用与网页相同的仓库资料，打包为本地资源。食谱目前是可搜索的资料库，不是个性化推荐。

健康对话固定在 Dock 正中央，图标与网页版相同。通过同一 `/api/chat` 流式展示回答、工具调用状态与耗时，可停止和重试。记餐作为 `meal-recording` Skill 复用原有识别/联网核对/多轮草稿服务；拍照、相册放在对话输入区，饮食页新增入口为“用健康助手记餐”或“手动记录”。草稿核对、表单编辑与显式保存保持原有行为；对话切换页面不丢失，保存失败沿用相同 ID 重试。训练页仍只读，健康助手对话具有网页版已有的训练与每日状态工具边界。

健康报告详情使用系统 WebView 加载 API 返回的 `render.document`，与网页复用同一份完整文档，保留生成时的 CSS、SVG、响应式布局和原生折叠阅读。旧版报告的主题样式也由服务端包装后统一显示。正文独立滚动，右上角菜单提供数据来源与重新生成，刷新按钮重新读取报告。报告脚本禁用，外部跳转受限；手机端不再把 HTML 降级为普通文字。更新后需要重新安装 APK。

活动统计现提供日期范围、类型筛选、汇总、运动节奏和构成，以及搜索、排序和分页详单。点按每次活动打开 Garmin 完整指标与分圈详情，训练计划里的已完成活动也使用相同详情。

健康报告列表按日期、状态、标题、摘要分层，顶部切换日报/周报，右上角提供定时设置；后台刷新保留已有报告。
