# healthy · 网页端

网页导航、浏览器图标与添加到主屏幕的名称统一为 `healthy`，使用纯叶片 Logo；SVG 母版和导出方式见 `assets/brand/`。

网页端导航是“健康首页”，以及身体状态、运动训练、饮食营养三个栏目。健康首页为只读数据驾驶舱：紧凑展示电量、睡眠、准备度与步数，直接汇总所选日期的饮食与营养、身体信号、近期运动、个人记录，以及最近已完成的日报/周报摘要。首页内容没有模块跳转链接，长摘要可原位展开；模块页面从导航进入。身体状态包含“生理指标”（Garmin 身体详情与趋势）和“个人记录”（本应用保存的状态文字）；运动训练包含“活动统计”（近期已完成活动）和“训练计划”（原 Garmin 运动日历）；饮食营养包含“饮食记录”（手机餐食与营养统计）、“食谱推荐”（食谱库，个性化推荐待实现）和“膳食指南”（公开核心推荐与宏量营养素标准原文）。活动统计提供时间/类型筛选、运动汇总与趋势、可搜索排序和分页的活动详单，每次活动可展开读取 Garmin 详情与分圈。其他待扩展内容没有伪装成已完成。

生理指标页按“睡眠与恢复、身体指标、日常活动、训练与表现”分组展示 24 张统一单列宽度的指标卡，涵盖训练负荷/重点、HRV 七天平均与基线、每周强度活动、体重目标、身体年龄、喝水、楼层、呼吸、血氧、血压、FTP、最大摄氧量、乳酸阈值及上次活动；指标使用适合各自含义的图形，保留历史趋势与详情。数据缺失和读取失败分开显示，最近体重与运动能力标明记录日期。

身体状态数据展示身体电量日内曲线、睡眠评分与阶段、训练准备度和恢复因素、夜间心率/HRV、压力分布与佳明步数目标；详情面板提供对应的观测数据和健康助手对话入口。生理指标按需加载 7/30 天的电量、睡眠、静息心率、HRV、压力与步数，缺失日期保留空值并断线。训练计划按月展示实际活动和计划训练，部分接口失败时保留明确提示。日期与页面保存在 URL，支持刷新和浏览器前进/后退。提供桌面/手机布局及深浅主题。个人记录按月份展示经对话保存的原文，同一天可有多条。

饮食管理已连接共享餐食 API，按日展示照片、食物、来源、估算依据及营养汇总；缺失值不补零，不完整时标明部分合计。运动日历与健康助手训练安排由独立训练模块提供；页面展示不代替佳明写入后的回读核对。健康助手对话使用流式事件展示等待时间、Garmin 工具状态和 Markdown 回答；文字与工具调用按发生顺序显示，完成后保留相同顺序，不折叠。等待时可停止生成。已在 3060 完成真实模型与 Garmin 只读查询验证；手机端已通过共享 API 同步饮食记录，健康助手可调用 get_meals 查询。

运行方式见根目录 README。Compose 前端在 `http://localhost:3060/` 提供网页并通过 `/api/` 代理读取数据；API 直连端口 `8060` 仅本机可用。

报告详情、每日饮食与单餐、健康助手回答、生理及营养趋势、展开的活动/训练、食谱详情提供图标形式的长图分享入口。共用 `share.js` 从现有内容生成浅色 PNG，支持完整预览与下载；浏览器支持文件分享时额外显示系统分享图标。导出在浏览器内完成，不上传生成图片。

“食谱推荐”页面目前连接 PostgreSQL 食谱库，提供配图浏览、菜名/配料搜索、分类、分页及完整配料与做法；个性化推荐尚未实现。它独立于手机饮食记录；

饮食记录的近七天趋势提供「营养 / 热量」两种视图：营养以统一克数刻度显示蛋白质、碳水和脂肪柱状图；热量以同一 kcal 坐标显示饮食摄入、Garmin 总消耗和估算缺口（总消耗减摄入）。图例可隐藏曲线，悬停或点选日期才显示数值；计算口径收纳在说明按钮中。SVG 按容器实际像素重绘，不拉伸固定画布。缺失数据断线，已记录餐食中有热量未填全时不计算缺口；全天漏记仍可能使缺口偏大，今天显示为暂估。总消耗复用 `/api/health/history?metric=calories` 的每日摘要缓存，不叠加训练或活动热量。
