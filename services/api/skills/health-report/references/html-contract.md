# healthy报告视觉与 HTML 约定

本契约由 renderer 实现；实际会话只使用任务提示中的 html_contract 声明支持的类、元素、SVG 属性和 CSS 属性。模型交付正文，宿主提供完整文档、CSS、隔离和主题桥接。不要生成 `doctype`、`html`、`head`、`body`、`style` 或 `script`。

## 视觉语言

风格来自healthy当前界面：清晰、温和、留白适量，系统中文无衬线字体，数字使用等宽数字。卡片圆角 18px，细边框，阴影很轻；保持整份报告的标题、图注、间距一致。图表可以有自己的组织形式，整体不另造品牌。

颜色引用主题变量，值由渲染层注入并随应用主题切换，模型不硬编码颜色。

| 用途 | CSS 变量 | 当前浅色参考 |
| --- | --- | --- |
| 页面、卡片、次级区域 | `--bg`、`--surface`、`--surface-alt` | `#f4f6f8`、`#fff`、`#f8fafb` |
| 正文、说明、边界 | `--text`、`--muted`、`--line` | `#23323b`、`#6c7b85`、`#e9edf0` |
| 主色与恢复 | `--teal`、`--teal-soft` | `#178477`、`#e9f5f1` |
| 睡眠 | `--indigo`、`--indigo-soft` | `#7263c3`、`#f0edfa` |
| 心率与需关注项 | `--coral`、`--coral-soft` | `#da6b6b`、`#fceded` |
| HRV | `--cyan`、`--cyan-soft` | `#3a96af`、`#eaf5f8` |
| 活动 | `--orange`、`--orange-soft` | `#d38a3d`、`#fcf3e8` |

颜色并不单独承担好坏含义，必须结合文字与标识；指标变化未必越高越好。深色主题由相同变量映射，不新增自己的深色背景。

## 可组合的排版

renderer 提供下列通用类，不是固定报告栏目。可以自由嵌套组合，按内容决定是否使用。

| 类名 | 作用 |
| --- | --- |
| `health-report` | 唯一正文根，最大宽度 1200px，居中，自适应内边距 |
| `report-lead` | 开篇核心结论，较大字号；不是每一段都强调 |
| `report-section` | 一个主题及其上下间距，默认单列通栏展开 |
| `report-card` | 有边界的分析、统计或证据组，默认 100% 宽度 |
| `report-number`、`report-unit` | 数值及单位，数字等宽 |
| `report-muted`、`report-caption` | 说明/图注；最小字号 12px |
| `report-note` | 数据局限或需要解释的口径 |
| `report-table-wrap` | 大表格独立横向滚动，页面自身不横溢 |
| `report-actions` | 建议的文本列表，不承载可执行按钮 |

### 单列流与「一天一行」排版要求
1. **严格单列全宽阅读流，拒绝左右两栏**：正文必须自上而下线性排版，**严禁使用左右两栏分列（禁止使用两栏的 report-grid、report-grid-2 或左右并排分割的文本/卡片）**。所有章节、分析段落、图表、大卡片均应占满单行通栏宽度，保证在桌面端与手机端都有顺畅自然的单列纵向阅读体验。核心指标卡片若需横向一览，仅限在顶部开篇单行紧凑排列 3–4 个关键数字，正文严禁左右分栏。
2. **多日对比严格「一天一行」**：周报或跨日对比时，每日明细必须采用「一天一行」（Row per day）的结构化表格（置于 `report-table-wrap` 内），周一至周日每行对应一天，横向打通展示当天的「日期、睡眠/HRV、主要运动及消耗、饮食摄入、日末电量/压力」，整齐通览，禁止把不同天的数据打散到左右双栏或分列卡片中。

优先使用类名；若需要特殊构图，允许宿主 schema 中明确开放的内联布局属性，例如 `display`、`gap`、`grid-template-columns`、`align-items`、`flex-wrap` 和使用主题变量的颜色。renderer 对宽度、定位与 CSS 值有边界；不要依赖固定宽度、绝对定位或未声明类名才能读懂内容。

允许的语义元素包括 `article`、`header`、`section`、`footer`、`div`、`span`、`h1`—`h4`、`p`、`strong`、`em`、`small`、`ul`、`ol`、`li`、`blockquote`、`figure`、`figcaption`、`table`、`caption`、`thead`、`tbody`、`tr`、`th`、`td`、`details`、`summary`、`br`、`hr`、`time`。使用正确标题层级、表头及语义。宿主提供报告页标题，正文可以从 `h2` 开始。

## 图表

使用内联 SVG（`svg`、`title`、`desc`、`g`、`path`、`line`、`polyline`、`rect`、`circle`、`text`、`tspan`），以 `viewBox` 配合 `width="100%"` 自适应。不要使用外部图片、字体或 CDN，不输出 JS 图表。SVG 通过 `fill="var(--teal)"` 等主题变量配色，几何与路径可以自由创作。

每个图都需要明确的问题、日期/单位、可读坐标或直接标注，附文字结论与可展开数值表。稀疏数据优先用点、表或直接数值，缺失区间不要连成趋势。小屏避免过多坐标标签，正文必须在没有悬停、点击图例或执行脚本时仍完整可读。

## 嵌入限制

不输出脚本、事件属性、外部 URL、链接、图片、表单、按钮、iframe、对象、SVG 外部引用、动画或 `foreignObject`，CSS 不使用 `url()`、导入和固定/绝对定位。可展开内容使用原生 `details/summary`。宿主负责主题与高度，不需要模型写通信代码。

不要用模型生成的按钮表达「已完成安排」「立即修改训练」等业务能力；建议写成普通文本，报告外的健康助手讨论入口由宿主实现。
